# 截图分层复刻与原生可编辑演示文稿精修技能

由助手直接读取材料、构建对象、处理素材、核验并交付文件。用户的原生编辑要求优先于其他技能默认的整页框架图片方案。保留本技能的分层、原生构建、透明素材和回填技术方案，按以下最高制作原则执行。

### 最高制作原则：原图一比一还原与原生可编辑同时达标

以当前原始图片为唯一视觉参照，最终演示文稿必须尽最大程度一比一复刻。此原则高于技能中的其他制作取舍；参考文件和历史经验不得降低它的优先级。不得以“允许轻微视觉差异”为理由放宽验收。

严格保留原图文字、字体、字号、颜色、位置、尺寸、间距、线条、形状、圆角、透明度和前后层级。原图有什么就还原什么，不擅自美化、重新设计、改变布局或配色、简化元素，以及增加、删除或改写内容。确实无法判断的属性记录待确认，不擅自改成更好制作的样式。

不得为了可编辑而牺牲原图效果，也不得为了外观一致而牺牲原生编辑能力。发现技术限制时继续定位和修正；仍有未解决差异则列明具体位置，不能宣称已一比一达标。用户本次另行明确指定的局部修改作为例外单独登记，其余区域仍以原图为准。

## 一、先确定本次材料的职责

| 材料 | 决定什么 | 不代表什么 |
|---|---|---|
| 当前截图或图片 | 外观、内容、配色、布局、轮廓及图片主体 | 不意味着必须把截图作为底图 |
| 与原图对应的原始演示文稿 | 原始图片素材、字体信息及对象的裁切与显示属性 | 不授权拿其他页面或其他文稿的素材替换当前原图内容 |
| 参考演示文稿 | 拆分粒度、对象类型及用户可编辑的属性 | 不授权改变参考图的设计 |
| 最新底稿 | 回填目标、画布、导航、页脚和未修改页 | 不能被同名旧稿替代 |
| 用户确认的满意版本 | 本次允许复用的成果和验收基准 | 不等于任意旧版均已达标 |

已有信息不重复索取。只对读不清的具体文字、存在歧义的目标页或不能判断的转角提问。保持原文字、括号、百分比、数据及出处；不猜写和补数。

新建独立任务目录，保存输入清单、原文件摘要，以及素材、预览、检查和交付子目录。原文件与满意版本只读保留。历史路径和数量不是默认参数。

若输入已是可编辑演示文件，直接保留其原生对象和关系，按指定范围修改；避免先栅格化再重新识别。

## 二、按用户会操作的功能元素拆分

| 内容 | 实现方式 | 必须能够操作 |
|---|---|---|
| 普通标题、正文、数值、图例 | 原生文本框 | 改字、字体、字号、颜色及段落样式 |
| 用户指定为文本框的色区 | 带填充文本框，或有文本框能力的原生自由曲线 | 改文字、底色、边框；复杂轮廓可编辑顶点 |
| 面板、标题条、色块、标签 | 独立原生形状；斜边按实际轮廓构建 | 分别改填色、边框、尺寸及位置 |
| 背景 | 幻灯片原生背景填充；窗景、光影、曲带等另列为装饰层 | 从「设置背景格式」更换底色、渐变或背景图片，装饰可独立移除，不影响前景 |
| 圆点、心形、柱形、箭头、分隔与连接线 | 独立原生图形 | 单独改色、移动、缩放 |
| 人物、冰山、复杂插画及质感图标 | 一张完整的独立透明图片 | 整体移动、缩放、替换，无重复残片 |
| 水面、环境过渡色 | 与主体分离的原生色层或渐变 | 独立换色，并与主体边界衔接 |

判断拆分单位时考虑“用户移动它时，希望整体动还是部分独立动”。人物和完整插画不碎切；框架和普通文字不合并到整页图片。禁止用整页截图铺底再覆盖少量文本框。没有指定组合时保持功能元素可独立选择，只有用户需要整体操作时才建立组合。

不规则文本框必须在同一个原生自由曲线对象中同时具有可修改的文字、可修改的填充颜色及可编辑的顶点；一张轮廓图片叠文字或只查询顶点数量，均不能证明这三项能力已经同时实现。

### 制作前锁定背景与带填色文字的编辑方式

- **背景可更改：** 默认保留原图设计，将整页底色设在幻灯片原生背景属性中；窗景、光影、纹理和曲带等另列为可独立隐藏或移除的装饰层。换色后，页边和可见空隙须确实显示新背景；不允许用不透明的整页对象盖住新底色。**去除背景且仍能更改：** 只移除场景背景及其装饰，保留标题、卡片、色框、插画、导航等前景；未指定新底色时使用原生白底。去背景不等于导出透明图片。
- **指定色区做文本框：** 每个指定色区的文字、填色与边框放入同一个原生对象。按原图采用矩形、圆角或自由曲线；保留斜边、弧边等不规则轮廓时，让文字、填色和顶点在同一对象上可编辑。改成简洁色框须有用户授权；删除被替代的旧字、旧色块和重复轮廓。
- **插画附带可编辑字标：** 将旧字标从图片层清干净并修补底部，重建原生文字。如果整体移动时字标应随图一起走，只组合该图片和字标，并确认组内文字仍可编辑；可独立移动的图注保持分离。明暗两种底色都要检查主体浅色细节、真实孔洞及边缘残留。

典型症状和检查顺序见[背景换色、色框与透明插画](references/复刻与动效故障排查.md#背景换色色框与透明插画)。

### 复杂图片的编辑范围

普通文字可独立修改；色块可独立改色；不规则文本框可修改文字、填充和顶点。复杂插画的“可编辑”默认仅指整张独立图片可移动、缩放和替换，不代表内部头发、衣服、五官或其他细节可单独编辑。

用户要求插画内部细节也独立可编辑时，需额外进行矢量化或原生图形重建，并分别登记和验证这些部件；未实际完成时不能承诺内部编辑能力。额外拆分仍须保持原图外观，不能以碎片化处理代替完整主体的正常交付。

### 每页对象登记表

制作前建立每页对象清单，制作和修正后更新；使用[对象登记模板](assets/对象登记模板.json)填写实测值，不把空模板当作检查记录。

| 必填项 | 记录要求 |
|---|---|
| 对象编号、对象名称 | 页面内唯一编号，并对应最终文件中的对象标识；一个源元素映射多个对象时逐一列出 |
| 原图坐标和尺寸 | 源图实际像素的横坐标、纵坐标、宽、高，并记录源图完整尺寸 |
| 原图颜色 | 文字、填充、线条颜色；渐变色标及透明度按需补充，未知项不得猜写 |
| 原生对象类型 | 独立文本框、原生形状、具有文本体的自由曲线、原生背景或独立透明图片 |
| 是否允许独立编辑 | 列出文字、填色、边框、顶点、移动、缩放、替换等适用能力 |
| 具体验收方式 | 对应实际操作、保存重开、局部差异图和无残留检查；记录状态及证据文件 |

文字、色块、轮廓及复杂主体分别与登记表核对，确保每个需要编辑的源元素都有对应对象，没有遗漏、重复或隐藏旧内容。

艺术字是否保留图片按当前要求决定，不把普通标题一律归为艺术字。原图里有图表不等于已恢复数据：未恢复原始数据表时，只声明图形或标签可编辑，不宣称图表数据可编辑。

## 三、执行顺序

1. **登记对象。** 按每页对象登记表记录原图内容、坐标尺寸、颜色、前后层级、对象类型、独立编辑能力和验收方式。参考文件只用于判断拆分方式。
2. **确定坐标与文字样式。** 所有位置先统一到源图实际像素；缩略图测量值按两个方向的缩放率换回。优先读取与原图对应的原始文稿的字体和主题字体信息；只有图片时，识别字形、粗细、衬线、字面和字宽等特征。核查电脑是否安装原字体，不能把设置了字体名称当作实际可用；找不到时选择当前可用且外观最接近的替代字体，记录原字体或识别依据、安装检查、替代字体及差异。按[字体识别与还原](references/原生对象与回填.md#字体识别与还原)处理后，重新核对字号、字宽、行距和文字位置。先定字体、粗细、字号、行距，再定位；关闭不需要的自动适应。磅值按当前画布换算，不套用历史比例。
3. **建立干净背景。** 先构造完整可换色底色或渐变，再放置其他对象。背景不得携带后续要重建的文字、旧卡片、标签或图片主体。按[背景与透明素材](references/背景与透明素材.md)处理复杂区域。
4. **重建原生框架。** 建立面板、标题条、标签、简单图形和环境层；需要改字的色区本身应有文本框能力。斜边、圆角及底框按[原生对象与回填](references/原生对象与回填.md)分别量测和构建。
5. **准备完整透明主体。** 按“原始文稿提取 → 原图抠取或遮罩保留原始像素 → 必要修复 → 最后才使用图像生成工具重生”的优先级执行，详见[图片素材提取与还原](references/背景与透明素材.md#图片素材提取与还原优先级)。优先提取与当前原图对应的原始图片，并还原裁切、缩放、旋转等显示属性；只有截图时，优先按主体轮廓抠取、遮罩和透明处理，保留原始像素。原素材确实无法提取或修复时才重生，并记录原因与真实来源。重生须实际传入参考图，对主体造型、构图、尺寸、颜色和边缘做外观对照，不符则继续修正；不因生成成功就接受替代设计。原图抠取与重新生成分别如实标注，不把带背景的矩形裁块冒称透明主体。
6. **放置普通文字。** 保持内容、层级与颜色；文字框填色与文字颜色分别设置。先核文字样式和换行，再修位置。
7. **处理指定局部。** 用户指出斜边、缝隙或残片时，前景、外框及底层一起检查；不以遮盖色块代替修复。
8. **需要时原位回填。** 使用最新底稿替换指定页，保留一套正确导航、当前栏目高亮和页序。未要求回填时交付独立页。
9. **循环核验最终版本。** 按下一节完成原图同尺寸渲染、叠加、差异图、局部放大和实际编辑测试；发现差异继续修正，每次修改后重新检查受影响区域，交付前再做一次整页全量对照。不能只检查一遍就交付，预览和记录必须对应最终文件摘要。

任务以本次质量要求为准。此前网页转换的耗时目标、模型接口设置和后台队列不作为本技能的前置条件；使用当前环境可用工具完成工作。工具缺失时说明受影响的具体检查或素材，不虚构调用结果。

## 四、验收必须同时覆盖对象与视觉

- **原图同尺寸视觉对照：** 用目标演示软件将最终页面导出为与原图完全相同像素尺寸的图片；不得先缩小、拉伸或自动配准再充当同尺寸验证。生成原图与渲染图的叠加图、绝对差异图及误差记录，检查错位、色差、边缘偏差和遗漏。整页与文字、图形、斜边、圆角、图片主体的局部放大都要看；不能只依赖肉眼、数值、对象数或结构中的某一项。
- **差异修正闭环：** 为差异登记对象编号、区域、现象、修正方法、复检证据和状态；持续修正可定位差异。数值阈值仅用于定位，不是降低一比一要求的合格线。无法完全消除的字体渲染或抗锯齿差异也要说明，未经核实不得归因；未解决项不能被总平均误差掩盖。
- **改字和改色试验：** 在验证副本中实际修改文字内容、文字颜色、文字框填充、普通面板填充及页面背景，保存并重新打开确认。更换与原色明显不同的背景色，检查页边、栏间和前景间隙确实变色，确认没有被整页装饰或母版图形挡住。逐类验证带填色文本框，不能用一个矩形的成功替代自由曲线的测试。
- **图片操作试验：** 实际移动、缩放并替换独立图片，保存重开检查位置、尺寸和替换结果；检查透明边缘及整体完整性。
- **不规则文本框试验：** 在同一个对象上实际改字、改填色，并通过演示软件界面或原生节点编辑接口改变至少一个顶点位置，保存重开确认三项同时保留。记录具体方法；只查询 `Nodes.Count` 和 `HasTextFrame` 不算完成编辑顶点试验。
- **移开检查：** 在验证副本先移动或隐藏指定色区、文字、标签及箭头，检查原位；再移开插画及其附着字标，最后隐藏全部前景核对背景。每一层都不得露出旧文字、旧色块、重复人物或残片；只看空背景不能证明插画或色框内部无残留。保留的独立前景须与对象登记一致。
- **轮廓检查：** 分别核左右斜距、圆角切线、前景与外框，不能出现无意浅色三角条。原生查询顶点数量与文本框能力；没有界面操作记录，不声称逐点手工拖拽。
- **图片检查：** 检查真实透明通道、白色主体、完整轮廓、矩形底块、重复、缺边及与水面的衔接。完整图片不切成零碎部件。
- **文字检查：** 标题、小字、百分比、括号、叉号、问号逐项对照；字界测量仅作筛查，同时查看压缩整页和必要局部，不以单一溢出阈值替代视觉判断。
- **两类文件检查：** 包结构及关系检查、目标演示软件实际打开和原生渲染分别完成。结构检查通过不能证明文件一定能打开，也不能证明视觉达标。
- **回填检查：** 总页数、目标页标题、导航文字、高亮及页脚正确；无重复页。对未改页面做关系感知的内容对照；只有确实核对相应数据后才能声称逐字节保持。

全部破坏性操作仅在验证副本中执行。除用户明确指定的改动外，交付稿保持原图的文字、颜色、背景、图片和顶点；若曾从验证副本恢复，恢复后必须重新保存、打开、渲染并做同尺寸对照，不能把改过样式的测试稿当最终稿。

可用随包工具做对象清点、包关系检查及本机原生打开检查：

```powershell
python -X utf8 '<技能目录>/scripts/audit_pptx.py' '<最终文件.pptx>' --output '<检查目录>/对象与打开检查.json' --office --preview-dir '<预览目录>'
```

同尺寸渲染与差异对照示例；多页文件按当前原图逐页执行，页码必须对应：

```powershell
python -X utf8 '<技能目录>/scripts/audit_pptx.py' '<最终文件.pptx>' --output '<检查目录>/同尺寸原生检查.json' --office --preview-dir '<预览目录>' --reference-image '<原图>' --reference-page 1
python -X utf8 '<技能目录>/scripts/compare_visual.py' '<原图>' '<预览目录>/原尺寸对照/page_001.png' --pptx '<最终文件.pptx>' --output-dir '<本轮对照目录>' --objects '<本页对象登记.json>' --audit-record '<检查目录>/同尺寸原生检查.json'
```

不加 `--office` 时，实际打开、顶点查询、文字字界和渲染必须标为待确认。该工具不验证截图相似度、不代替完整格式规范校验，也不自动证明移开后无残留；这些要另行实际完成并记录。

检查工具依赖见随包 `requirements.txt`。视觉工具只生成证据，差异记录仍保留“待确认”，不能自动宣称一比一通过；使用 `--crop-ids` 指定登记对象可生成局部放大图。回填页面的导航与原图主体若不同比例，按参考说明登记固定偏移和等比对照区域，不能拉伸迁就画布。

### 完整安装包与调用命令核对

交付和更新安装包时，逐一核对 `assets/对象登记模板.json`、`references/背景与透明素材.md`、`references/原生对象与回填.md`、`references/案例与证据.md`、`references/复刻与动效故障排查.md`、`scripts/audit_pptx.py`、`scripts/compare_visual.py` 和 `requirements.txt` 真实存在且包含在包中；正文链接必须解析到对应文件。

检查两个脚本的帮助及参数定义，逐项匹配本节示例中的位置参数和选项，再用测试文稿与测试图按示例实际运行。原生打开需要的运行环境、当前可用字体及依赖缺失如实记录。脚本参数通过、依赖存在、实际调用成功分别记录，不把文件存在当作脚本已运行；不能只交付说明文字而遗漏工具文件。

原尺寸渲染与差异图保留供程序数值对照。模型看图时使用随包工具在 `_ai小图` 内生成的压缩副本，每轮最多四张，未变图不重复查看。局部放大以原尺寸数据裁出后再生成分析图。

## 五、只报告有证据的结果

检查状态使用“已验证”“待确认”“不适用”。记录对象或页面位置、检查方法、证据文件及剩余问题，不把计划写成已执行，不把现象猜测写成确定根因。

用户提供的两个历史达标案例按需查看[案例与证据](references/案例与证据.md)，不能自动替代本次文件验收。对象总数只是清点结果，不能代替改字、改色、顶点、移动与背景检查。

最终交付须同时覆盖：原图最大程度一比一外观、独立原生文字、可改色普通色块、文字／填色／顶点均可编辑的不规则文本框、独立可改背景、可移动缩放替换的完整图片、移开无残留，以及目标演示软件打开正常且布局不变形。某项未验证或未通过时，不能称为完整达标。

交付最终演示文件、同版本压缩预览、每页对象登记表和检查记录；记录最终文件、原图及原尺寸渲染图的摘要，并保留对应叠加与差异证据。需要时附透明素材及验证副本。只有用户要求时提供便携文档或交付压缩包。简明说明实际可编辑范围及未解决差异，不增加审批步骤。

## 六、与其他技能结合

以用户当前要求和本技能的原生可编辑标准为准。可参考已有图片分层技能的坐标校验、素材登记、视觉对照及合成方法；不要沿用把所有卡片和图表框架合成一张图片的默认做法。

使用图像生成工具时遵循其实际传图与透明输出要求；生成后的素材和原生框架分别处理。用户没有要求创建网站、部署服务或接入模型接口时，不扩展到这些任务。

遇到字界误判、标签移开后露底、透明边缘残片、同尺寸证据版本不一致，或用户要求给已复刻的文稿加动画时，按需读取[复刻与动效故障排查](references/复刻与动效故障排查.md)对应章节。它补充故障定位和验证方法，不替代第四节验收，也不把案例里的字体、坐标、时长或判断阈值设为默认参数。

用户明确要求增加或保留原生动画时，动态演示文稿制作技能负责模板选择、对象时间轴和播放检查；本技能负责原生编辑能力、静态外观和回填关系。截图复刻后再加动画时，以指定的可编辑底稿为载体，在副本中借用模板的动画机制；模板外观只有在用户明确授权改版时才可采用。已有动态底稿只做局部修改时，保留其时间轴和目标对象关系。两类任务都要区分播放过程与动画完成后的停留画面；仅做静态复刻不触发新增动画。
