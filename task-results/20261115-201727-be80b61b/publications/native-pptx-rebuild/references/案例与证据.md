用户说明中的“36个文字框、26个原生图形、9张完整图片、无组合”用于说明一种拆分方式，不是通用数量配额，也不证明新文件达标。

历史版本被认可不等于可以放宽当前一比一要求。当前原图是唯一视觉基准；案例只复用经过核验的技术办法，不复用旧配色、近似轮廓或视觉容差。新任务须重新登记对象，提供最终文件对应的同尺寸对照、差异修正和实际编辑证据。

原技能引用的十四处轮廓、十七个顶点、每百像素一英寸、海水起点及某一页导航高亮均属于特定页面。新任务重新测量；不复用固定参数覆盖当前材料。

## 可迁移的故障处理

| 信号 | 处理动作 | 证据要求 |
|---|---|---|
| 色框不能直接改色 | 重建原生可填充对象；需要文字时保留文本体 | 实际改填色、保存重开 |
| 移动后露出黄字或旧框 | 查完整清除范围和底图，修复源内容 | 移开或隐藏后的原区域预览 |
| 斜边旁有浅色三角 | 同时修前景和底框的轮廓及描边 | 局部与整页对照 |
| 主体带矩形底、重复残片 | 按素材优先级提取、遮罩或修复完整主体，必要时才透明重生；清除旧主体，环境层独立 | 明暗底透明检查及移动试验 |
| 技术检查通过但打不开 | 检查媒体关系、内容类型、内部路径 | 最终文件原生打开与渲染 |
| 字体更改后发生错位 | 先固定样式和行距，再校准框和位置 | 原生字界及整页预览 |
| 替换后多了一页或错高亮 | 回到最新底稿原位替换，保留一套导航 | 页数、页序、标题和高亮检查 |

现象存在而未完成单变量验证时，具体根因标为待确认；不要把历史推测写成普遍事实。
