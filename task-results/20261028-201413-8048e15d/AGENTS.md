# 任务结果自动上传规则

- 用户已授权：每次代码任务完成，并通过该项目已有的必要检查后，自动提交并推送本次任务的结果代码，无需每次再次询问是否上传。
- 任务开始前检查当前分支、暂存区和工作区，明确本次任务范围。存在其他任务的改动时，优先隔离本次任务，不能将无关改动混入提交。
- 完成任务后，仅暂存本次任务涉及的文件或改动，使用中文说明提交内容。不要为了上传而对整个工作区执行无差别暂存。
- 推送至用户指定的远程仓库和目标分支。没有指定目标时，使用已经确认的上游配置；远程地址或目标不明确时，先取得缺失配置，不猜测上传目的地。
- 不上传凭据、密钥和应当忽略的本地配置，不跳过项目已有的必要提交检查。
- 使用普通推送。遇到冲突、远程历史分叉、认证失败或权限不足时，保留本地结果并报告原因，不自动强制推送、重写历史或覆盖他人的改动。
- 推送失败后，不重复创建相同提交。修复原因后补推已经存在的任务提交。
- 每次任务结束时，用中文说明本次结果是否已经提交、是否已经推送，以及仍需处理的实际问题。
