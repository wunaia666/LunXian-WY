# 小鲸鱼语音纠偏记录（2026-10-30）

## 一句话结论

线上"不像"是链路问题，不是参数问题：日常语音一直在跑**二代模型的 instruct2 路径**，这条路几乎丢掉参考音的音色——基频只有 324–333 Hz，声纹诊断余弦 0.23–0.24，而参考原声是 480 Hz。

现在日常链路已经改成 **三代模型 + 逐句合成 + 每句音高校准**：同一段长台词基频 461 Hz，余弦 0.67，短句 453 Hz / 0.60。旧链路是 333 Hz / 0.23。

## 实测数据（同一段台词，同一条原声）

| 路径 | 基频 | 声纹余弦（只作诊断） |
|---|---|---|
| 参考原声 | 480 Hz | 1.00 |
| 线上短句（二代 instruct2，旧） | 324 Hz | 0.24 |
| 三代短句（无校准） | 378 Hz | 0.55 |
| **三代短句 + 音高校准（新日常）** | **453 Hz** | **0.60** |
| 线上长段（二代 instruct2，旧） | 333 Hz | 0.23 |
| 三代长段（无校准） | 414 Hz | 0.60 |
| **三代长段 + 音高校准（新日常）** | **461 Hz** | **0.67** |

声纹余弦只能做相对排查，不等于听感百分比。

## 已经改动的内容

1. **新增三代语音服务** `E:\sss_test\tools\cosy_server3.py`：与二代服务同一套 HTTP 约定（/health、/tts、/admin/reload、/admin/analyze），只做日常语音需要的语气合成与分段拼接。
2. **引擎开关**：`dafeiyu_assets/voice_config.json` 的 `_模型.engine`，`cosyvoice3` 走三代，`cosyvoice2` 走二代。`cosy_supervisor.sh` 按该字段选服务。
3. **分段合成**：长台词按句切到 22 字以内逐句合成再拼接，避免整段一次生成造成的音高与音色漂移。
4. **音高校准（本次新增）**：`tts.py` 的 `_pitch_match` 在每句合成后测基频，用 ffmpeg 的 `asetrate+aresample+atempo` 把整句对齐到参考音中位数 480 Hz（共振峰同步移动，等同原素材被变调的效果），单句最多 ±4 个半音，超过就不动。
   - 配置项：`cosy_pitch_match: true`、`cosy_target_f0: 480`。
   - 基频估计算法与语音服务 `/admin/analyze` 完全一致，避免两边口径不同把校准推过头（第一版就是因为口径不一致被最大幅度夹住，已经修正并重新生成）。
5. **语音工作台适配**：`xiaojingyu_voice_studio.py` 的稳态档位不再走二代专有的 cross_lingual，改为中性语气指令。
6. **试听页生成器** `tools/build_voice_audition_page.py`：把候选音频和页面一起放到桌面。

## 验证

- 语音相关回归：`test_voice_corrections` 7 项全部通过。
- 端到端：三代服务 + 音高校准下 `tts.py` 正常合成短句（3.82 秒）与长段（21.09 秒、6 块），参考音校验通过，未切换其他音色。

## 还没有定的事

1. **听感验收**：以上只是可测指标，不能代替耳朵判断，也没有声称达到九成相似。
2. 音高校准的力度可以调：现在按"整句对齐到 480 Hz"处理，如果听起来太尖，可以把 `cosy_target_f0` 降到 450 左右，或把 `cosy_pitch_match` 关掉。
3. 长段每句基频仍有 382–486 Hz 的波动，这是三代模型自身的抖动。

## 回滚方法

关掉音高校准：`voice_config.json` 里 `cosy_pitch_match` 改 `false`（改完无需重启服务）。

整套回退到二代：`_模型.engine` 改成 `cosyvoice2`，再执行：

```powershell
wsl.exe -d Ubuntu -- bash /mnt/e/sss_test/tools/cosy_wsl.sh stop
wsl.exe -d Ubuntu -- bash /mnt/e/sss_test/tools/cosy_wsl.sh start
```
